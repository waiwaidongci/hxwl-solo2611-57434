# 回收分拣错投预警

`hxwl-solo2611-5` · 分类与风险解释

收料员按批记录入线前的快速抽样和输送带负荷，质检员在班末回填固定抽检 20 件的结果。班组长用已结案历史回看不同预警阈值，决定下一班优先派人复核哪些批次。

## 模拟客户与工作流

禾川再生资源分拣中心｜2 条分拣线、24 名作业员，日处理约 35 吨可回收物

- 入线抽样和班末质检各存一张表，交班时靠批次号手工对账。
- 班组长凭经验抽批，忙时容易漏看外观混杂、标签难辨的来料。
- 调整抽查力度以前，只能估计复核量，看不到过去会漏掉多少错投。

分拣班组对达到阈值的批次安排人工复核，质检班组用留出期的误报量估算复核工时，并检查漏报批次是否需要加抽，班组长据此决定下一班试行的阈值。

## 业务模块

- 来料批次台账
- 预警阈值试算
- 错投复盘与处置
- 班组交接收件箱

## 计算口径

按作业日留出最新的整天记录。仅用较早作业日计算四项入线特征的均值和标准差，再拟合带 L2 正则的二元逻辑回归。实际错投定义为固定抽检 20 件中至少 1 件被投进错误料仓。仅导入已结案批次，保证训练期质检结果在留出期开始前已知。阈值只用于把留出期概率转换为复核建议。留出期反复试阈值属于回看，定下的阈值应在之后的独立作业日验证。

样例输入为 `禾川分拣质检_20261109-20261120.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 23 日 07:50，收料员导入《禾川分拣质检_20261109-20261120.csv》，核对 12 个作业日、96 个结案批次。
2. 08:05，质检员核对 HS-1120-01 的批次号、四项入线指标及班末抽检标签。
3. 08:15，班组长留出 11 月 17 至 20 日 32 批，将 11 月 9 至 16 日 64 批用于拟合。
4. 08:25，将阈值从 0.55 降至 0.30，建议复核从 7 批增至 13 批，误报从 2 批增至 7 批，漏报从 3 批降至 2 批。
5. 08:40，质量复核组按结果中的批次号翻查漏报及误报原单，核对现场处置记录。
6. 09:00，班组长把下一班采用的阈值和复核安排发给分拣运行班组与成品质量复核组。
7. 16:30，质检员回填新批次抽检结果，汇总到后续独立作业日的验证记录。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18314`，API `http://127.0.0.1:19314`，数据库宿主端口 `17814`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 PostgreSQL 16 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
