# 回收分拣错投预警

`hxwl-solo2611-5` · 分类与风险解释

收料员按批登记入线前的快速抽样和输送带负荷，质检员在班末按版本回填固定抽检 20 件的结果。班组长用发布时刻已结案的历史给下一班来料打分，按复核名额选出优先复核批次。

## 模拟客户与工作流

禾川再生资源分拣中心｜2 条分拣线、24 名作业员，日处理约 35 吨可回收物

- 入线抽样和班末质检各存一张表，交班时靠批次号手工对账。
- 班组长凭经验抽批，忙时容易漏看外观混杂、标签难辨的来料。
- 调整抽查力度以前，只能估计复核量，看不到过去会漏掉多少错投。
- 抽检记录交班后乱序补报，同一批次可能有多版结论，人工对账难以判断该采信哪一版。

分拣班组按名单安排人工复核，质检班组按当前误报量估算复核工时，并检查漏报批次是否需要加抽，班组长据此调整下一班的复核名额。

## 业务模块

- 来料批次台账
- 预警阈值试算与名单发布
- 错投复盘与处置
- 班组交接收件箱

## 计算口径

名单发布时刻冻结两件事：训练只用此刻已结案的班末抽检；参评批次只含此刻已登记的最新作业日来料。先按批次取最新抽检版本，同一最高版本结论冲突的批次列为待核，不进入训练也不计误报、漏报。入线四项特征用训练期均值和标准差标准化，再拟合带 L2 正则的二元逻辑回归；实际错投定义为固定抽检 20 件中至少 1 件被投进错误料仓。

对参评批次按错投概率从高到低排名，同分按来料批次号升序，取复核名额内的批次组成名单。名单发出后补传的来料和更正的历史只更新当前复盘，不改变参评批次和入选结果；重复导入、重复补报或重跑同一名单不会重复计数。未抽检批次单列，不计入误报或漏报。

样例输入为 `禾川分拣质检_20261109-20261121.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 21 日 07:55，收料员导入《禾川分拣质检_20261109-20261121.csv》，核对 12 个结案作业日和下一班来料登记。
2. 08:00，班组长以发布时刻 08:00 冻结历史：96 批已结案记录用于拟合，8 批下一班来料参评。
3. 08:05，按复核名额 3 批生成名单：HS-1121-01、HS-1121-02、HS-1121-04，同分按批次号升序。
4. 08:10，质量复核组按名单翻查原单；名单发出后补传的 HS-1121-09 不进入本次参评批次。
5. 16:30，质检员回填下一班固定抽检，乱序补报按版本取最新，同版结论冲突的 HS-1121-04 列为待核。
6. 17:00，用原名单复盘当前结果：命中 1 批、误报 1 批、漏报 2 批，未抽检 2 批单列。
7. 次日，班组长按误报量和漏报名单决定是否加抽，并调整下一班复核名额。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18314`，API `http://127.0.0.1:19314`，数据库宿主端口 `17814`。

后端单元测试可在 `backend` 目录执行 `python -m unittest discover -s tests -t .`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 PostgreSQL 16 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

结果页可用原名单复盘最新抽检版本，各批的发布时抽检版本、当前抽检版本和当前误报、漏报都保留在运行结果中。核心实体为 CSV 数据批次、分析运行（含名单快照）、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
